What happened

Artificial intelligence coding assistants have moved from a novelty to an ordinary part of the working day for many software teams. The tools complete half-written functions, generate unit tests, translate code between languages and explain unfamiliar repositories in plain sentences. Two industry surveys published this month suggest that a majority of professional developers now open an assistant at least once per working day, and that the most common uses are writing tests and reading other people's code. Managers report that routine tasks contract, which frees engineers for design work. Yet the evidence also carries a warning: models sometimes produce code that compiles, passes a weak test and still hides a subtle error …

Vocabulary to know
• assistant (n) — A program that helps a person complete a task, often by suggesting the next step. In context: She keeps the coding assistant open all day but reads every suggestion before accepting …
• workflow (n) — The ordered set of steps a team follows to turn work from start to finish. In context: Adding a review step to the workflow slowed releases but cut the number of …
• generate (v) — To produce something, especially text or code, by machine rather than by hand. In context: The tool can generate tests for a function in seconds.
• unit test (n. phr) — A small automated check that one piece of code behaves as expected. In context: No change reaches the main branch without a passing unit test.
• legacy (adj) — Relating to old program code that is still in use and usually hard to change safely. In context: The assistant explained the legacy module better than the missing documentation did.
• repository (n) — The stored collection of a project's files and their revision history. In context: A new engineer can now explore the whole repository without asking for a tour.
• review (n. / v) — A careful examination of work by another person before it is accepted. In context: Human review remains the last line of defence against plausible but wrong code.
• vulnerable (adj) — Exposed to damage, attack or error. In context: Payment modules are considered too vulnerable to accept machine-written changes.
